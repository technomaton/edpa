## Symptom

In a repo with a `conventional-commit` gate (which EDPA's own work rules
mandate), a non-trivial change with no ticket has **no commit message that
passes both hooks**:

| Subject | EDPA gate | CC gate |
|---|---|---|
| `no-ticket: fix typo` | pass | **reject** — not `type(scope): desc` |
| `chore(no-ticket): fix typo` | **reject** | pass |
| `chore: fix typo` | **reject** | pass |

## Cause

`_ESCAPE_PREFIXES` holds only bare forms (`no-ticket:`, `WIP:`, `[no-ticket]`)
and matching is `subject.startswith(...)`, so a CC-scoped variant never matches.

The bypass-CC shape was deliberate — the rules doc says escapes "intentionally
bypass CC scope to make opt-outs visible in `git log --oneline`". The intent
(visibility) is right; the implementation defeats itself in exactly the repos
that follow EDPA's own CC guidance.

## Why this matters more than the inconvenience

The dead end pushes people to `git commit --no-verify`, which bypasses *every*
hook — including pre-commit ID safety — and leaves no trace in the commit
message. The current state actively selects for the worst available option.

## Fix

Accept CC-scoped escape variants alongside the bare ones:
`chore(no-ticket):`, `chore(wip):`. These satisfy a CC gate *and* stay visible
and greppable in `git log --oneline`, which is what the original design wanted.

Document the scoped form as preferred; the bare form only works where no CC
gate exists.
